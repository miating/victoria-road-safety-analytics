# Power BI

The dashboard is saved as a **Power BI Project (PBIP)**. A PBIP is a folder of text files rather
than one binary `.pbix`, so the data model, the DAX measures and every report page are reviewable
in Git like the rest of the code.

The dashboard design is in [`docs/dashboard_design.md`](../docs/dashboard_design.md).

| Path | Contents |
|---|---|
| `victoria_road_safety.pbip` | Open this file in Power BI Desktop |
| `victoria_road_safety.SemanticModel/definition/` | The data model in TMDL: tables, relationships, sort orders, formats |
| `.../definition/tables/_Measures.tmdl` | **All DAX measures**, with descriptions and format strings |
| `victoria_road_safety.Report/definition/` | Report pages and visuals in PBIR (one JSON file per visual) |
| `tools/build_report.py` | Generates the report pages from code |
| `tools/pbir.py` | Helpers for writing PBIR JSON |
| `screenshots/` | One image per page, so the report can be reviewed without Power BI |

Not in Git (see `.gitignore`):

- `.pbi/cache.abf`, the imported data, which is rebuilt by **Refresh**
- `.pbi/localSettings.json`
- any `.pbix` file

## Open the report

1. Install Power BI Desktop (free, from the Microsoft Store).
2. Load the database with `python -m src.pipeline`.
3. Open `powerbi/victoria_road_safety.pbip`.
4. Click **Home > Refresh**. When asked for credentials:
   - choose **Database** and sign in to PostgreSQL. A read-only login is recommended; see [`sql/security/01_powerbi_reader.sql`](../sql/security/01_powerbi_reader.sql).
   - credentials are stored on your machine, never in the project files.
   - a local PostgreSQL usually has no SSL certificate; accept the prompt to connect without encryption.
5. The maps use the **Azure Maps** visual, which needs you to be signed in to Power BI with a work or school Microsoft account. Without that sign-in, every other visual still works.

## How the report was built

| Step | Approach | Why |
|---|---|---|
| Connection | PostgreSQL connector, **Import** mode | About 1M rows and monthly data. Import is fastest and supports all DAX; DirectQuery would query PostgreSQL on every click |
| Tables | The 3 facts and 14 dimensions from the `analytics` schema | Slicers must filter every visual, which needs the related star schema. The `vw_*` views serve SQL users |
| Relationships | 21, all one-to-many and single direction, dimension to fact | Facts are never related to each other; the measures cross between them with `TREATAS` |
| Model settings | Date table, sort orders, lat/long categories, hidden keys | Applied directly in the TMDL files, see below |
| Measures | 19 measures in `_Measures.tmdl` | One documented place for every calculation |
| Report pages | Generated by `tools/build_report.py` | Layout is code: reviewable, repeatable, and consistent across pages |

## Editing

**Measures and model.**

- Edit the `.tmdl` files with Power BI Desktop closed, then reopen the `.pbip`.
- Alternatively, edit in Power BI Desktop and save; the TMDL files are rewritten.
- Either way, `git diff` shows exactly what changed.

**Report pages.** These are regenerated from code:

```bash
python powerbi/tools/build_report.py
```

- Close Power BI Desktop first, and do not save on close, or it overwrites the generated files.
- The script replaces every page, so layout changes belong in `build_report.py`, not in Power BI Desktop.

## Refreshing after a new data load

1. Run `python -m src.extract.download` and then `python -m src.pipeline`.
2. In Power BI Desktop, click **Home > Refresh**.

Table names, columns and keys are stable between loads, so the report needs no changes.
